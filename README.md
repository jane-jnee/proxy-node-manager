# 独立节点管理 v2.2.0

适用于自有 Linux 服务器。支持 VLESS + TCP + Reality、VMess + WebSocket、Shadowsocks；每次创建同协议 1–20 条独立节点。

## 安装或更新

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/jane-jnee/proxy-node-manager/main/installer.sh)
```

菜单应显示 **v2.2.0**。后续输入 `menu` 打开本地版本。更新入口备份并替换本地管理脚本，不会因为更新程序就清空节点或累计用量。

## 主菜单

```text
1) 新增节点（完成后自动显示链接）
2) 查看全部节点
3) 导出节点链接
4) 节点管理
5) 流量管理
6) 服务与工具
0) 退出
```

- **新增节点**：进入后按回车默认选择 VLESS，也可以选 VMess 或 Shadowsocks。
- **节点管理**：修改端口、重新生成 UUID/密码、删除节点。修改凭据和删除仍需明确确认。
- **流量管理**：启用及查看用量、调整累计额度、手动清零选中节点。
- **服务与工具**：查看服务状态、检查并重启、更新本地 `menu` 入口。

二维码生成、二维码安装菜单及相关代码已移除。没有卸载服务器上可能被其他软件使用的二维码软件包。

## 创建节点

依次填写数量、显示名称、连接地址、Reality SNI（仅 VLESS）、端口和每条额度；最后核对信息并确认。

- **显示名称**只是客户端备注，支持中文、空格和常用特殊符号；不能仅为空白或含控制字符。创建多条时自动加编号。
- **连接地址**填写客户端能访问的服务器 IP/域名，不含 `https://`、端口或路径。
- **SNI**填写实际用于 Reality 握手的域名，不能把节点名称填在这里。格式校验不等于已验证服务器到该域名的 TLS 握手。
- **端口**必须在云安全组及现有防火墙放行。默认自动分配本机未占用的端口，不代表云端安全组已开放。
- **额度**按上传加下载累计。`1000` 为 1000 GB，`0.5` 为 500 MB，`0` 为不限量；不按月自动重置。

每创建成功一条，立即单独显示完整导入链接，并追加保存到 `/etc/sing-box/node-manager/created-links-时间.随机值`，文件权限设置为 600。文件包含该批新节点的连接凭据，请只在自己的设备间使用。批量创建后面的节点失败，前面成功节点及已导出的链接保留。

**每次新增都会生成新的端口、UUID 和 Reality 密钥。** 改名称后再次新增，是另一条节点，不是给旧节点改备注；应导入本次显示的完整新链接。

## 关于“自定义名称后不可用”

离线对照未复现名称导致认证参数改变：英文、中文、空格及保留符号名称的运行配置和 VLESS 连接字段相同，只有链接的 `#` 备注不同。新版将备注与连接字段分开说明，增加创建前核对，并明确输出新链接。

这不等于已确认真实网络连通。如果仍失败，应对照新链接的服务器地址和端口、云安全组、SNI，以及客户端/服务日志继续定位。不要发布包含 UUID、密码或私钥的完整运行配置。

## 流量服务与恢复

自动额度管理需要 systemd + nftables，使用独立 `inet pnm_traffic` 表；不清空系统防火墙，也不自动放行安全组。保留 v2.1.1 对 nftables 1.0.2 缺失 JSON 表注释的兼容修复。

若旧版流量服务正在失败循环，先执行 `systemctl stop proxy-node-quota.service`，再运行上面的更新命令。更新后进入 **5 → 1** 恢复并查看；已有节点需要检查/重启时进入 **6 → 2**。

累计记录保存在 `/etc/sing-box/node-manager/traffic-state.json`。只有 **5 → 3** 明确确认后才清零选中节点；不要删状态文件来修复错误。正常情况下约 5 秒保存一次，突然断电可能损失最近未保存的少量用量。

```bash
systemctl status proxy-node-quota.service --no-pager -l
journalctl -u proxy-node-quota.service -b -n 60 --no-pager
systemctl status sing-box.service --no-pager -l
```

## 适用范围与验证

本工具管理自己创建的独立监听端口，原有其他节点保留为只读；同服务器节点默认共用出口 IP。Docker 转发、共用端口及特殊中转需要另行适配。计量包含网络协议开销和重传，不是精确财务计费系统。

本次通过配置/链接、菜单、自动导出、输入校验和 nft 兼容离线检查。没有把这些结果称为用户 VPS 的真实连通测试，Linux 服务和内核额度仍需目标服务器验证。详情见 `TEST-REPORT.zh-CN.md` 与 `verification.json`。

本定制版源自 [dabadabader/install](https://github.com/dabadabader/install)，已去除广告并重构独立节点管理。运行配置、备份、密钥、导出链接和流量记录属于服务器私有数据，不应上传此代码仓库。
