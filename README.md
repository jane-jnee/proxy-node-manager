# 独立节点管理 v2.2.2

适用于自有 Linux 服务器。支持 VLESS + TCP + Reality、VMess + WebSocket、Shadowsocks；每次创建同协议 1–20 条独立节点。

## 安装或更新

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/jane-jnee/proxy-node-manager/main/installer.sh)
```

菜单应显示 **v2.2.2**。后续输入 `menu` 打开本地版本。更新入口备份并替换本地管理脚本；更新管理程序本身不会清空节点或累计用量。

## 主菜单

```text
1) 新增节点（完成后自动显示链接）
2) 查看全部节点
3) 导出节点链接
4) 节点管理
5) 流量管理
6) 服务与工具
0) 退出
```

- **新增节点**：回车默认选择 VLESS，也可选 VMess 或 Shadowsocks。
- **节点管理**：修改端口、重新生成 UUID/密码、删除节点。
- **流量管理**：查看累计用量、修改额度、手动清零选中节点。
- **服务与工具**：查看状态、检查配置并重启、更新 `menu`，以及卸载本工具。

创建节点后自动显示完整导入链接，并将本批新链接保存到 `/etc/sing-box/node-manager/created-links-时间.随机值`，文件权限设置为 600。批量后续节点失败时，前面已成功创建的节点和已导出链接保留。二维码生成和安装选项已移除。

## 卸载管理工具

更新到 v2.2.2 后，输入 `menu`，依次选择 **6 → 4**。

1. 若仍有本工具创建的活动节点，先到主菜单 **4 → 3** 删除这些节点；卸载功能不会替你批量删除正在使用的节点。
2. 再进入 **6 → 4**，查看卸载范围。
3. 输入完整大写 `UNINSTALL` 才执行；回车或其他输入取消。

卸载移除本工具的 `menu` 快捷命令、本地管理脚本，以及确认归属且为空的流量服务、依赖文件和 nft 表，并退出菜单。

**保留** sing-box 内核及共享服务、其他节点及其配置、历史累计用量、节点记录、已导出的链接和原有备份。卸载前会另外保存一份 `/etc/sing-box/node-manager/uninstall-backup-时间.随机值/` 备份。备份可能包含节点凭据，请只在自己的服务器上保管。

卸载仅支持标准安装路径。若发现路径链接、被其他程序修改的文件、仍存在的流量规则，或无法确认服务依赖，会停止相应操作并显示原因。发生部分步骤失败时，按提示核对保留的管理文件和备份；不要删除累计记录来强行通过检查。卸载不是自动清理整个 `/etc/sing-box`，也不会卸载共享依赖软件包。需要恢复入口时，重新运行上面的安装命令。

## 创建节点时的字段

- **显示名称**只用于客户端备注，支持中文、空格和常用特殊符号；不能仅为空白或含控制字符。多条节点自动编号。
- **连接地址**填写客户端能访问的服务器 IP/域名，不含 `https://`、端口或路径。
- **SNI**填写实际用于 Reality 握手的域名。格式检查不能替代实际握手验证。
- **端口**需要在云安全组及现有防火墙放行。自动分配本机未占用的端口不代表公网已开放。
- **额度**按上传加下载累计。`1000` 为 1000 GB，`0.5` 为 500 MB，`0` 为不限量；不按月自动重置。

每次新增都会生成新的端口、UUID 和 Reality 密钥。改名称后再次新增是另一条节点，应导入本次生成的完整新链接。

## 流量服务与恢复

自动额度管理需要 systemd + nftables，使用独立 `inet pnm_traffic` 表；不清空系统防火墙，也不自动放行安全组。保留 nftables 1.0.2 缺失 JSON 表注释的兼容处理及 v2.2.1 前台配置锁最多等待 15 秒的修复；后台 tick 仍在锁忙时跳过本轮。

若旧版流量服务正在失败循环，先执行 `systemctl stop proxy-node-quota.service`，再运行更新命令。更新后到 **5 → 1** 恢复并查看；已有节点检查/重启到 **6 → 2**。

累计记录位于 `/etc/sing-box/node-manager/traffic-state.json`。只有 **5 → 3** 明确确认后才清零选中节点。正常情况下约 5 秒保存一次，突然断电可能损失最近未保存的少量用量。

```bash
systemctl status proxy-node-quota.service --no-pager -l
journalctl -u proxy-node-quota.service -b -n 60 --no-pager
systemctl status sing-box.service --no-pager -l
```

## 适用范围与验证

本工具管理自己创建的独立监听端口；同服务器节点默认共用出口 IP。Docker 转发、共用端口及特殊中转需要另行适配。计量包含网络协议开销和重传，不是精确财务计费系统。

本版在 Linux 临时目录通过 17 个卸载回归场景、127 项断言，涵盖取消、节点阻止、文件归属、符号链接、非空表、依赖解除失败、停止失败和卸载后数据保留。systemctl、nft、路径和锁边界使用模拟。

另通过 3 个 Linux 隔离场景：取消、活动节点阻止卸载、确认卸载后实际 systemd 依赖解除及原生空 nft 表移除；共享服务仍在运行，配置、内核及历史记录保留。服务进程使用 sleep 替身，未验证代理转发。

v2.2.1 的 5 个真实 Linux 协议/额度/systemd 隔离场景和 3 个真实 flock 场景作为历史结果保留，未计作 v2.2.2 重新执行。更早的 Windows 核心互通与离线测试同样只作为历史基线。详情见 `TEST-REPORT.zh-CN.md` 与 `verification.json`。

发布包未在生产服务器执行卸载，也未替换生产安装。包内仅包含代码、说明、来源、验证摘要和校验和，不包含服务器配置、密钥、完整节点链接或私有测试日志。
